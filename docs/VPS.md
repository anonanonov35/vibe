# ВАЙБ — тату-студия

Одностраничный сайт на Next.js 16.3.4 (App Router), React, TypeScript и Tailwind CSS 4.

## Локальный запуск

Требуется Node.js 24 и npm. В PowerShell используйте `npm.cmd`, если выполнение `npm.ps1` отключено.

```sh
npm ci
npm run dev
```

Откройте http://localhost:3000. Файл `.env.local` уже создан для локального просмотра; случайный пароль панели находится в строке `ADMIN_PASSWORD`. Он не попадает в Git. При новом клонировании скопируйте `.env.example` в `.env.local` и задайте собственный пароль длиной минимум 24 символа.

## Что работает

- Разделы о студии, три мастера, портфолио с фильтрами и полноэкранным просмотром, прайс, FAQ, отзывы, запись и адрес.
- Мобильное меню, клавиатурная навигация, закрытие просмотра по Escape, reduced-motion.
- Форма: Telegram или телефон, выбор мастера, комментарий, согласие, клиентская и серверная проверка; защита по Origin, honeypot и ограничение частоты.
- Серверная отправка через Telegram Bot API. Успех отображается только при ответе `ok: true`. Без реквизитов ботa API возвращает 503 и честное уведомление. При ошибке заполненные поля сохраняются.
- `/admin`: публикация / удаление фотографий работ и мастеров. Доступ к изменениям проверяется на сервере. Пароль не сохраняется в localStorage и cookies. Интерфейс панели открыт, но загрузка и удаление защищены паролем; метаданные галереи и фотографии публичны по назначению.
- Загрузка JPEG / PNG / WebP до 8 МБ, проверка декодером, ограничение 40 млн пикселей, удаление EXIF, преобразование в WebP до 1600 px. До 150 файлов. Новая фотография мастера заменяет отображаемую; старые можно удалить в панели.
- Метаданные, canonical, Open Graph 1200×630, Twitter card, SVG favicon, Apple icon, sitemap и robots.
- Docker multi-stage / standalone, непривилегированный пользователь и постоянный том.

## Подключение Telegram

Создайте бота через BotFather и начните с ним диалог либо добавьте в нужную группу. Укажите на сервере:

```dotenv
TELEGRAM_BOT_TOKEN=токен_бота
TELEGRAM_CHAT_ID=идентификатор_чата
```

Секреты задаются только серверными переменными. Не добавляйте префикс `NEXT_PUBLIC_`, не отправляйте `.env.local` в Git. Код отправки: `src/app/api/booking/route.ts`. Реальная доставка требует этих реквизитов и доступа VPS к `api.telegram.org`; в разработке внешние сообщения не отправлялись.

## Фотографии и тексты

1. Откройте `/admin` и введите пароль из `ADMIN_PASSWORD`.
2. Выберите «Портфолио» или «Фото мастера», заполните название, выберите файл и нажмите «Опубликовать».
3. Для мастера показывается последнее загруженное фото. Первое опубликованное фото работы заменит демонстрационные эскизы портфолио.

Имена, описания мастеров, цены, вопросы и отзывы находятся в `src/lib/content.ts`. Имена мастеров — заполнение макета; SVG-иллюстрации предусмотрены до появления настоящих портретов. Придуманные отзывы явно помечены как примеры. Четыре SVG-эскиза — демонстрационные иллюстрации, не фотографии выполненных работ.

Цены перенесены из ТЗ без предположения «за час» или «за сеанс»: единица тарификации в ТЗ не указана. Адрес «Москва, ул. Примерная, 199» перенесён из ТЗ и должен быть заменён реальным. Поэтому карта представлена ссылкой на поиск, без вымышленной геометки.

## Развёртывание в Dokploy через GitHub

1. Создайте GitHub-репозиторий и загрузите проект без `.env*`, `node_modules`, `.next` и `data` (исключены через `.gitignore`).
2. В Dokploy создайте Application, подключите GitHub-репозиторий и выберите сборку **Dockerfile**, путь `./Dockerfile`, контекст `.`.
3. Задайте переменные из `.env.example`. `NEXT_PUBLIC_SITE_URL` — реальный адрес, например `https://your-domain.ru`, без завершающего `/`. Передайте его также как build argument `NEXT_PUBLIC_SITE_URL`: sitemap и robots формируются при сборке.
4. Задайте отдельный надёжный `ADMIN_PASSWORD` (минимум 24 символа), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `DATA_DIR=/app/data`.
5. Добавьте **Volume Mount**: постоянный том `studio-data` → `/app/data`. Каталог должен быть доступен UID/GID 1001. Без тома фотографии потеряются после пересоздания контейнера. Резервируйте этот том отдельно от репозитория.
6. Подключите домен к порту **3000** и включите HTTPS. Выполните Deploy. При изменении домена выполните новую сборку.
7. Проверьте главную, `/admin`, загрузку тестового фото и доставку тестовой заявки в Telegram.

Альтернатива для локального Docker: `docker compose --env-file .env.local up --build -d`.

`TRUST_PROXY=false` по умолчанию: лимит формы общий для одного процесса (5 попыток за 10 минут). Для индивидуальных лимитов настройте reverse proxy, который **перезаписывает**, а не пропускает пользовательский `X-Real-IP`, и только затем включите `TRUST_PROXY=true`. Ограничьте body size в reverse proxy до 9 МБ. Лимитер хранится в памяти; для нескольких реплик нужен общий Redis или лимиты на ingress. Текущее файловое хранилище рассчитано на один экземпляр приложения и постоянный том.

До приёма реальных заявок замените адрес, данные мастеров и демонстрационные отзывы, заполните сведения об операторе и сроки хранения в `src/app/privacy/page.tsx`. Страница обработки данных подготовлена как редактируемый шаблон. Реквизиты организации в ТЗ отсутствуют.

## Проверки

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e
```

E2E использует установленный Google Chrome (`channel: chrome`), отдельный сервер на порту 3100 и отдельный каталог `test-results/gallery-data`. В тестах нет реальных Telegram-реквизитов. Если Chrome не установлен, установите его либо измените конфигурацию Playwright на доступный Chromium.

Скриншоты desktop/mobile сохраняются в `artifacts/`. Тесты проверяют фильтры, lightbox, FAQ, меню, переполнение, форму, SEO-ресурсы, защиту API и полный цикл загрузки/удаления изображения.
